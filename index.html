Cleaning methodology

Quality rules applied where they matter.

Instead of treating every anomaly the same way, the notebook uses field-specific rules to preserve useful records without hiding invalid data.

01 / Identity

Deduplicate and repair IDs

Duplicate patient rows are removed and missing patient, doctor, and appointment identifiers are generated.

02 / Text

Normalize categories

Names, gender, specialties, branches, statuses, visit reasons, and payment fields use consistent casing and labels.

03 / Contact

Validate communication fields

Phone numbers and email addresses are standardized and invalid values are handled explicitly.

04 / Dates

Parse mixed date formats

Registration, appointment, and invoice dates are converted into dependable database-ready values.

05 / Numeric

Correct types and ranges

Ages, charges, and payments become numeric; impossible ages and negative financial values are addressed.

06 / Enrichment

Create analytical features

Patient ages are grouped into useful age bands, adding a ready-made dimension for demographic reporting.

Run the project

Reproduce the complete workflow locally.

The repository contains the source data, notebook, generated outputs, relational diagram, and SQL reporting script.

Python pipeline

  1. Install Python 3.10 or later and PostgreSQL.
  2. Create a virtual environment and install requirements.txt.
  3. Copy .env.example to .env and enter database credentials.
  4. Run healthplus_project.ipynb from top to bottom.
  5. Confirm the four cleaned CSV files and PostgreSQL tables.

SQL reporting

$ psql -h localhost -p 5432 \ -U postgres -d healthplus_db \ -f sql/healthplus.sql -- Patient, doctor, appointment, -- and billing reports
Reload behavior: the notebook currently uses if_exists="replace". Re-running the load replaces each table rather than appending records.
